## August 13, 2026 - Vision Prototype V1 - Tracking Data Analysis

### Objective
Analyze the tracking data produced by the vision system to establish quantitative baseline measurements of the target's position relative to the center of the camera frame.

The purpose of this stage of development was to move beyond visually observing the tracking system and begin using recorded data to measure its behavior.

### Work Completed
- Created a seperate Python analysis program for processing recorded tracking data.
- Installed and began using Pandas for reading and analyzing CSV data.
- Installed and began using Matplotlib for visualizing tracking data.
- Loaded the tracking data generated by the vision system into a Pandas DataFrame.
- Filtered the dataset to separate successful target detections from frames where the target was lost.
- Calculated the percentage of detected frames where the target was within the +- 20 pixel horizontal deadband.
- Calculated the percentage of detected frames where the target was within the +- 20 pixel vertical deadband.
- Calculated the percentage of detected frames where the target was simultaneously within both the horizontal and vertical deadbands.
- Calculated mean absolute tracking error for both axes.
- Calculated maximum absolute tracking error for both axes.
- Calculated RMS tracking error for both axes.
- Created a graph of horizontal tracking error versus time.
- Added reference lines to the graph representing the exact frame center and ±20-pixel deadband.
- Preserved missing tracking data as gaps in the graph rather than connecting separate periods of valid tracking.
- Configured the analysis program to save the horizontal tracking-error graph as a high-resolution image for documentation.

## What I learned
I learned how Pandas can be used to load CSV data into a DataFrame and how individual columns can be accessed and filtered based on conditions.

I learned that missing numerical values in the CSV are represented by Pandas as `Nan`. These missing values are useful becase they distinguish frames where no valid target position exists from frames where the target actually has a coordinate of zero.

I learned how multiple conditions can be combined when filtering a DataFrame. This allowed me to determine whether the target was within the horizontal deadband, vertical deadband, or both simultaneously.

I learned how Matplotlib can be used to graph tracking data over time. Initially, I graphed only the filtered detection data. This caused Matplotlib to draw a line between the last detection before the target was lost and the first detection upon the target being found again. I fixed this by plotting the original dataset, where the `Nan` values cause the graph to break during those moments where no target was detected instead of it filling the space.

I also learned the difference between RMS error nad mean absolute error. Mean absolute error represents the average magnitude of the tracking error, while RMS error gives greater weight to large deviations because the individual errors are squared before averaging. 

### Testing / Results
The first recorded test contained 540 processed frames where 310 of them contained a valid target detection.

The following baseline measurements were calculated from frames containing a valid target:
Metric | Horizontal (X) | Vertical (Y)

Center rate within +-20 px | 6.5% | 21.0%
Mean absolute error | 174.0 px | 107.1 px
RMS error | 221.0 px | 139.7 px
Maximum absolute error | 605 px | 325 px

The target was simultaneously within both the horizontal and vertical +-20 pixel deadbands during 1.0% of valid detection frames.

A horizontal tracking error graph was generated showing the target's displacement from the center of the frame over time. The graph includes the exact frame center and the boundaries of the +-20 pixel deadband. Periods where the target was lost appear as gaps in the plotted tracking data on the graph.

### Interpretation

These measurements establish a baseline for the stationary-camera version of the tracking system.

Because the camera cannot currently move, the system has no way to correct the displacement data shown with the X and Y errors.

These measurements will become more useful after a motorized pan-and-tilt mechanism is introduced. The same metrics can then be measured again under similar test conditions to determine how effectively the physical tracking system keeps the target centered.

### Current Limitations

- THe system still uses prerecorded video rather than a live camera feed.
- Target identification still relies on a fixed HSV color range.
- The largest qualifying green contour is assumed to be the desired target.
- The +-20 pixel deadband is a fixed value rather than being scaled according to camera resolution or field of view.
- Tracking error is currently measured in pxiels rather than angular displacement.
- The current dataset was produced using a stationary camera, so it does not yet measure closed-loop tracking performance.
- No physical pan-and-tilt mechanism is currently connected to the vision system.
- The current analysis represents a single test run and should not be interpreted as a complete characterization of system performance

### Next Step
Begin planning the physical two-axis pan-and-tilt system.

The next stage will determine the required hardware for converting the calculated horizontal and vertical tracking errors into physical camera movement. This will include selecting a controller, pan-and-tilt mechanism, power requirements, motors or servos, and a method for communication of commands from the vision software to the controller.

After physical movement is implemented, the existing data-logging and analysis system can be reused to compare the motorized tracker against the stationary baseline outlined here.
